# 芯链哨兵｜工具辅助与人工判断记录

本文件用来说明 AI 和脚本在项目中做了什么、没有做什么。它不是提示词汇编，也不把自动化检查写成模型准确率。

## 一、实际使用的环节

| 环节 | 工具完成的工作 | 人工保留的判断 |
| --- | --- | --- |
| 贸易数据 | 生成并迭代官方 API 查询、字段整理、伙伴清洗和 N2/N3/N4/V1/V2 计算 | 确认 Reporter 自报、HS8542四位口径、World/地区汇总处理和马来西亚/越南基准值 |
| 政治数据 | 整理 UNGA、ATOP 和 OECD TiVA 字段，检查国家键和年份键 | 确认 P1 公式、P2 的跨年覆盖边界和 2022 结构性补充不替代动态观测 |
| 政策文本 | 从 BIS《联邦公报》候选规则中按字段和关键词筛选待核对条目 | 区分“文本提到某国”和“法律明确适用于该国实体”，决定 P3 不进入主指数 |
| 验证与页面 | 生成主键、范围、公式、基准和敏感性检查，搭建三页离线网页原型 | 复核图表口径、缺失状态、企业扫描输入边界和现场演示路径 |

## 二、一次具体的纠错

早期文本筛选把“规则正文提到某个国家”当成“该国实体受到管制”。人工检查后发现，两者之间还隔着适用对象、产品范围、例外条款和第三国路径，因此把 P3 从国家分数中移出，改成独立的待复核政策证据层。企业扫描页也只接受 `manual_review_status=confirmed` 的用户输入记录，并明确写出“没有匹配到事件不等于没有法律风险”。

## 三、边界

- 工具没有填补缺失的 2022 动态 ATOP 数据，也没有把 2018 状态伪装成 2022 动态值。
- 工具没有根据新闻标题或国家提及自动生成法律结论。
- 工具没有把企业演示 CSV 写入核心国家面板。
- 15项检查只验证数据和公式的一致性，不代表因果效度、预测准确率或合规结论。
